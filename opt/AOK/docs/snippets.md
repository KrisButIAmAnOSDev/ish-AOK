# Snippets: the commands you keep

A snippet is a saved command line you can put on the prompt with one tap. It is
the feature dedicated SSH clients call "snippets", and it earns its place for
the same reason theirs do: when you are using iSH-AOK as a terminal for *other*
machines, the local shell's aliases, functions and history are all on the wrong
side of the connection. The long command with the flags nobody remembers has to
live on this side.

## Opening the list

Four ways in, because the one that is convenient depends on what you are doing:

- **Long-press the Paste key** in the row above the keyboard.
- **Cmd-J**, with a hardware keyboard.
- The **Switch Terminal** button — the one showing overlapping rectangles —
  lists **Snippets…** in its menu. This is the one to use with a hardware
  keyboard, which hides the key row the Paste key lives in; the same button
  then floats over the bottom-right of the terminal.
- In Workspace, the ☰ menu (the corner button, a long press on the desktop, or
  a window's own ☰) has **Snippets…**. See [workspace.md](workspace.md).

## A snippet is inserted, not run

Tapping a snippet puts its text on the command line and leaves the cursor
sitting there. Running it is a separate per-snippet choice — **Run on tap**, in
the snippet's editor — and it is off by default.

That is deliberate rather than timid. A library of saved commands that fire on
a mis-tap is a library of ways to destroy something, and the snippets worth
saving are exactly the ones worth reading once before they run. Turn **Run on
tap** on for the harmless ones you use constantly.

Multi-line snippets arrive as a bracketed paste rather than as typing, which is
what makes them usable at all: without the wrapper every newline would run
whatever came before it the moment it landed, and "insert, do not run" would be
a promise the list could not keep.

## The same library, from inside the guest

The list lives in two places at once. The app's own copy is what the sheet
reads and writes, so the list still works with the guest shut down. A JSON
mirror at `/AOK/persist/snippets.json` is what the **guest** sees — so snippets
can be edited in `vi`, kept in `git`, generated by a script, and shared between
roots, because [`/AOK/persist`](persist.md) is host-backed and mounted the same
way whichever root you booted. One library follows you from Alpine to Devuan.

```sh
cat /AOK/persist/snippets.json        # read it
vi /AOK/persist/snippets.json         # edit it; reopen the list to pick it up
```

It is an array of objects, pretty-printed with sorted keys so a `git diff` of
it is readable and stable:

```json
[
  {
    "id" : "6B1F2C7E-...",
    "name" : "Tail the web log",
    "run" : false,
    "text" : "sudo tail -f /var/log/nginx/access.log"
  }
]
```

Writing one by hand is fine. `id` may be omitted — one is generated — and `run`
defaults to `false`, so a name and a text are enough.

**Which side wins, when both have changed.** The guest file wins when it has
changed since the app last wrote it; otherwise the app writes the file. That is
decided by comparing the bytes, not by the modification date — a timestamp on a
file several roots can touch is not evidence of anything, while "these are not
the bytes we left there" is.

## Things worth knowing

- **A file that will not parse is left strictly alone**, and nothing is written
  over it. A half-finished edit in `vi` is still your work, so a broken file
  costs you the sync, not the file.
- **The mirror is read with a 1 MB cap.** That is a guard against a corrupted
  or wrongly-pointed file being read into memory wholesale, not a limit on how
  many snippets you may keep.
- **The `id` survives renames**, which is how editing a snippet updates the one
  you opened instead of appending a near-duplicate.
- **Swipe to delete, and Edit to reorder**; the order in the list is the order
  in the file.
